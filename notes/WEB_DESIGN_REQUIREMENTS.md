# Ilyenkov Archive Website Design Requirements

> Generated from brainstorming session. Approved design for the public-facing static website,
> generated by `scripts/build_web.py` and deployed through the existing `publish_public.sh` pipeline.

## 1. Overview

The Ilyenkov Philosophy Text Archive needs a public-facing website to serve three core functions:

1. **MD+PDF split-pane reading** — side-by-side display of Markdown corpus text and corresponding
   original PDF scan pages.
2. **Contributor guide** — a static page introducing the project to visitors, explaining how to
   submit PRs, navigate the source, and participate.
3. **Philosopher profiles** — trilingual (Chinese/English/Russian) introduction pages for all 7
   philosophers in the archive, covering life, career, and thought summaries.

## 2. Scope and Constraints

### Scope

| Philosopher | Role | Profile page | Works pages |
|---|---|---|---|
| Evald Ilyenkov | Central figure | Yes | Yes |
| Andrey Maidansky | Ilyenkov researcher | Yes | Yes |
| Baruch Spinoza | Intellectual source | Yes | Yes |
| Bonifaty Kedrov | Soviet dialectics | Yes | Yes |
| Teodor Oizerman | Soviet epistemology | Yes | Yes |
| Pavel Kopnin | Soviet dialectical logic | Yes | Yes |
| Lev Vygotsky | Cultural-historical psychology | Yes | Yes |

### Constraints

- **Static site only** — generated by a custom Python script, zero backend.
- **GitHub Pages hosting** — deployed from the public repository `hoshF/ilyenkov-archive`.
- **Integration with `publish_public.sh`** — `build_web.py` runs as part of the existing public
  export pipeline; output lands in `dist/public/docs/`.
- **No rights filtering at launch** — initially show all available Markdown corpus content; rights
  review proceeds independently and does not block site launch.
- **PDF scans remain unprocessed** — PDF files are served as page images via `<iframe>` or
  `<embed>`; no OCR text layer extraction is performed.

## 5. Page Specifications

### 5.1 Home Page (`index.html`)

- Project title and brief description (from `README.md`).
- Grid of 7 philosopher cards (name, years, role, link to profile).
- Links to works overview and contributor guide.
- Language: English (default), with Chinese/Russian toggles.

### 5.2 Contributor Guide (`guide.html`)

- Project overview (condensed from `README.md`).
- "How to Browse" section pointing to the reading pages.
- "How to Report Issues" — link to GitHub Issues with template guidance.
- "How to Submit a Pull Request" — step-by-step from `CONTRIBUTING.md`.
- "Project Structure" — directory tree overview.
- "Rights and Licensing" — summary from `RIGHTS.md` and `LICENSE`.
- Source data: `CONTRIBUTING.md`, `README.md`, `AGENTS.md`, `RIGHTS.md`.

### 5.3 Philosopher Profile Page (`philosophers/<id>.html`)

Three-language content in a single page (tab/button toggle: RU | EN | ZH):

| Section | Source |
|---|---|
| Header: name in all three scripts | `metadata/collections.json` |
| Life dates and career summary | `notes/*_SOURCE_SURVEY.md` + new `philosopher_profiles.json` |
| Thought summary (key concepts, contributions) | New `philosopher_profiles.json` |
| Works list (title, year, pages, link) | Collection `works_master.json` or catalog manifest |
| External links: Wikipedia, filorus.ru, institutional pages | Manual curation in profile data |

Template layout:
```
+-------------------------------------------------+
```

### 5.4 Works Overview Page (`works/index.html`)

- Browsable list of all works across philosophers.
- Filter by philosopher, language, work type.
- Each entry links to the work landing page.

### 5.5 Work Landing Page (`works/<author>/<work>/index.html`)

- Full metadata: title, author, year, edition, source URL, rights status.
- Chapter table of contents (from `work_manifest.json`).
- Links to chapter reading pages.

### 5.6 Chapter Reading Page (`works/<author>/<work>/chNNN.html`)

Split-pane layout:

```
+--------------------------------------------------+
|  Navigation: <- Prev Chapter | TOC | Next Chapter ->|
+------------------------+-------------------------+
|  Markdown Text (left)  |  PDF Scan (right)       |
|                        |                         |
|  ## Chapter Title      |  [PDF page as <iframe>  |
|  Text content...        |   or <embed>]           |
|  ...                   |                         |
|                        |                         |
|  Page marker: [p. 42]  |                         |
|                        |                         |
+------------------------+-------------------------+
|  Footer: source attribution, rights notice        |
+--------------------------------------------------+
```

- **Left pane**: Markdown rendered to HTML with clean academic typography.
- **Right pane**: PDF displayed via `<iframe>` or `<embed>`, scrolled to the page range
  specified in `page_map.json`.
- **Sync**: page markers in the Markdown (e.g., `[p. 42]`) optionally highlight the
  corresponding page in the PDF viewer. Full paragraph-level sync is out of scope for v1.
- **Responsive**: on narrow screens, stack vertically (MD on top, PDF below).

## 7. Build Pipeline

### 7.1 Script: `scripts/build_web.py`

```python
# Core functions:
build_index()              -> docs/index.html
build_guide_page()         -> docs/guide.html
build_philosopher_pages()  -> docs/philosophers/*.html
build_works_overview()     -> docs/works/index.html
build_work_landing()       -> docs/works/<author>/<work>/index.html
build_chapter_page()       -> docs/works/<author>/<work>/chNNN.html
copy_assets()              -> docs/assets/, docs/pdfs/
```

**Template engine**: Jinja2 (standard Python library-compatible).

**Input**: reads `metadata/collections.json`, walks each collection's corpus and scan paths,
reads `work_manifest.json` and chapter Markdown, generates static HTML.

**Output**: `dist/public/docs/` (synchronized with `publish_public.sh` target).

### 7.2 Integration with `publish_public.sh`

```bash
# Add to publish_public.sh (after existing checks, before git push):
echo "Building website..."
python3 scripts/build_web.py

# Then proceed with existing export and push logic:
python3 scripts/export_public.py
python3 scripts/export_public.py --verify
# ... push to public repo
```

### 7.3 Deployment

GitHub Pages configured to serve from `docs/` directory on the `main` branch of
`hoshF/ilyenkov-archive` (the public repository).

## 8. Technical Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Generator | Custom Python script | Reuses existing Python tooling, reads project-specific JSON/MD formats directly |
| Templates | Jinja2 | Well-established, minimal dependency |
| CSS | Hand-written | Lightweight, no framework overhead for text-heavy academic site |
| PDF display | `<iframe>` with `#page=N` | Browser-native, no PDF.js dependency |
| Search | Deferred (Fuse.js if needed) | v1 ships without; add client-side search later |
| Language toggle | CSS + minimal JS | Show/hide divs; no page reload |
| Chapter sync | Page markers in MD | Manual `[p. N]` markers; automatic scroll sync is v2 |

## 9. Non-Goals (v1)

- Full OCR or text-layer extraction from PDFs.
- Paragraph-level Markdown-to-PDF alignment.
- AI chat or interactive agent (static guide page only).
- User authentication or private content areas.
- Dynamic search backend.
- Automated chapter-to-PDF-page mapping (manual `page_map.json` for now).
- Multi-work comparison or cross-reference linking.

## 10. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Most texts not rights-approved for redistribution | Show all initially; add filtering later when rights review matures |
| Philosopher profile content must be written from scratch | `philosopher_profiles.json` created incrementally; ship with Ilyenkov first |
| PDF files may be large (>30MB) for browser loading | Use `<iframe>` with lazy loading; consider PDF thumbnail previews |
| Build script complexity grows with site features | Keep `build_web.py` modular; one function per page type |
| Content drift between private and public repo | `publish_public.sh` with `--check` mode enforces sync |
