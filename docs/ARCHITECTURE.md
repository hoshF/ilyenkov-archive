# 网站与仓库架构

## 定位

中文伊里因科夫不是 private 研究仓库的公开镜像，也不只是正文列表。它承担三项长期职责：

1. 面向中文读者系统介绍伊里因科夫本人、思想和著作；
2. 连接中文世界与国际伊里因科夫研究、会议、组织和交流；
3. 作为中文伊里因科夫小组全部公开出版物和项目成果的身份锚点。

## 信息架构

| 栏目 | 路由 | 职责 |
| --- | --- | --- |
| 伊里因科夫 | `/ilyenkov` | 人物、语境和阅读路径的导览 |
| ├ 生平 | `/ilyenkov/life` | 已公开生平事实的阶段性入口，不构成完整传记 |
| ├ 年表 | `/ilyenkov/timeline` | 已公开研究事实的统一时间坐标 |
| ├ 作品目录 | `/ilyenkov/works` | 以作品为单位连接公开书目来源 |
| └ 交往与活动 | `/ilyenkov/circle` | 已公开活动资料的主题入口 |
| 档案 | `/archive` | 进入已获准在本站阅读的文本 |
| 研究 | `/research` | 国际研究与交流地图 |
| ├ IFI | `/research/ifi/` | IFI 研究实体的简介、形成背景、活动方式、官方资源与主要 symposium 历史 |
| └ 伊里因科夫学术报告会 | `/research/readings/` | 伊里因科夫学术报告会的系列介绍、历史关系、资料入口和已公开会议记录 |
| 小组 | `/group` | 经过编辑选择的长期公共记录，按期归档小组以自身名义公开的研究、活动和阶段性成果 |
| 书籍 | `/books` | 统一维护成书的公开身份 |
| 近期动态 | `/updates` | 网站、小组、翻译、资料整理与研究工作的公开变化记录 |
| RSS | `/rss.xml` | 公开内容与近期动态的摘要订阅 |
| 关注与联系 | `/contact` | 获取更新、联系小组与表达长期参与意愿的事实入口 |
| 项目与权利 | `/about` | 解释边界和方法 |

栏目页之间保持互相可达。顶栏保持五个一级内容栏目；子页面由所属栏目页链接。页脚保留项目与权利、
小组，并提供近期动态、关注联系与 RSS 入口；首页与小组页也在相应上下文链接 `/contact/`，不把它加入
顶部导航。正文内部的链接是上下文相关的引用。网站结构测试会校验导航中每个链接都对应一个真实页面。

研究栏目逐步以研究实体组织入口：`/research/` 的 IFI 与 Readings 部分只保留简短介绍与详情链接。
IFI 详情页 `/research/ifi/` 复用现有 public 数据契约，按简介、形成背景、活动方式、官方资源与主要
symposium 历史展开。Readings 详情页 `/research/readings/` 使用已公开的系列记录与会议记录，按简介、
历史线索、资料与入口、已公开会议记录展开；会议列表是经过选择的公开历史节点，不是完整会议数据库，
不建立单届会议详情页。两页均采用 breadcrumb、普通 `SectionLayout` 与 `prose` 的单一正文流，不设
侧目录，不新增 CSS 或客户端 JavaScript。Researchers 与 Research Sites 保持当前展示，未建立其
详情页；两页不扩展公开字段，也不新增本站相关内容关系。

版式上只有三条长期约定：栏目页是“栏目定位在左、内容在右”的双栏；有明确父子关系的页面在正文前
显示位置导航，一级栏目不显示；文章正文保持单一阅读栏。具体的间距、断点与组件样式以
`src/styles/global.css` 和结构测试为准。

### 三类页面布局

网站统一的不是几何结构，而是信息层级、字体、spacing、metadata、breadcrumb、link、左右栏职责与
响应式思路。版式按**用户进入页面后的主要任务**分三类，不按 URL 或文件类型机械判断：

> 用户主要是在“了解一个栏目”、“读一篇东西”，还是“浏览一个结构”？

| 布局 | 用户任务 | 左栏 | 右栏 | 几何特征 |
| --- | --- | --- | --- | --- |
| 栏目页 | 了解这个栏目有什么 | 栏目身份与定位、极短的范围说明、少量栏目级导航 | 入口、列表、子栏目、主要记录 | 左栏轻；`grid-template-columns: minmax(0, 248px) minmax(0, var(--reading))` |
| 阅读型详情页 | 读一篇连续文本 | 只做阅读辅助：页内目录、少量位置跳转、必要返回 | metadata、主标题、摘要、连续正文、注释、来源、文末导航 | 正文保持阅读中心感：稳定行宽，尽量落在页面主体中央，不因辅助目录被推向右侧 |
| 结构型详情页 | 浏览一个结构，在多个成果／内容类型之间移动 | 页面表现的一部分：分类、结构、当前选择、内容类型、子入口、上下文、上一期／下一期、返回 | 当前主标题、metadata，以及当前选择对应的内容 | 不强求正文几何居中——左栏也是有效信息区域，允许左栏更宽、右栏整体偏右，两栏共同构成页面主体 |

三种布局的左右栏职责边界：

| 栏 | 承担 | 不承担 |
| --- | --- | --- |
| 左栏 | 当前位置与面包屑（位置导航）；本页或本期的结构索引；页内目录；分类与内容类型入口；上下级入口；返回入口；上一期／下一期 | 文章主标题；正文或主要研究内容；需要连续阅读的长篇说明 |
| 右栏 | 页面主标题与 metadata；摘要；正文；译文、研究、讨论、资料等主要信息 | — |

栏目页允许左栏承担“栏目身份”，但不塞入大量主体内容。栏目页默认使用栏目身份左置的形态；只有当
页内目录本身具有明显浏览价值时，才使用 `indexed` 形态（目录独占左栏、栏目身份与内容同处右栏）——
不能仅因为页面存在多个 `h2` 就让目录占掉左栏。阅读型与结构型详情页的左栏只列当前页面
**真实存在**的结构和去向，不显示尚未存在的栏目或成果类型；条目可以是跳转（指向右栏中真实存在的
锚点），也可以是当前页面的构成说明。右栏是完整文档：标题与正文同处一个阅读列，主标题不进入左栏。
单栏布局下左栏回到普通文档流，顺序是位置与结构、metadata、主标题、正文、篇末去向。

同一页面可以随内容在阅读型与结构型之间移动：本期只有一篇连续文章时它就是阅读型；某期真的包含
研究、译文、讨论、资料等多种成果时，左栏列出这些真实类型，页面自然成为结构型，不需要另立一套
视觉系统。判断依据是当前内容，不是预留的栏目位。

页面几何与左栏宽度都由 token 与 `SectionLayout` 的变体决定，没有写死在某个页面的宽度值上；需要
更宽的结构栏时，在带页面限定选择器的规则里覆盖 token（见 `src/styles/global.css` 的
`.section-layout` 一节），不改默认列宽。

首页不属于这三类，它是站点的门面版式。内容依次为站点标题与定位、从哪里开始、最新内容、近期动态、持续关注，
沿用现有字体、间距和文本链接，不增加卡片或新的视觉系统。“最新内容”从已有公开译文与小组按期记录
聚合少量入口，显示内容类型、标题、适用的作者及有明确语义的日期：有可靠公开日期的记录优先按公开日期
倒序，未记录本站公开日期的译文随后沿用档案顺序，原文年份只作书目信息。“近期动态”显示同一动态数据源的
最近四条，并链接完整动态页。完整动态页只按时间倒序展示日期、简短说明与可选链接，不生成动态正文页。
“持续关注”只用简短说明与文本链接进入 `/contact/`；联系页沿用普通正文布局，依次说明获取更新、联系与参与，
提供 RSS 订阅文本入口，不提供表单或客户端脚本。小组页保留身份、工作与长期成果说明，不重复联系页的邮箱与参与文案。

`/rss.xml` 由 `src/pages/rss.xml.ts` 使用 `@astrojs/rss` 在构建时生成，复用小组公开记录与动态数据，
只输出摘要与链接。RSS 和全站 HTML 的订阅发现链接使用 `astro.config.mjs` 的同一个 `site` 基址，
不需要客户端脚本、服务端运行时或新增 HTML canonical 标签；数据与日期规则见[内容管线](CONTENT_PIPELINE.md)。

页面是静态 HTML，不做 hydration。全站只有一段客户端脚本：译文页把页内目录当前所在的章节标成
`aria-current="location"`。它是渐进增强，只随 `/archive/<id>` 输出；没有它时目录仍然是一组可用的
锚点。再要加脚本，先确认同一件事没法用 HTML 或 CSS 做到。

## 两个仓库

```text
private 研究系统
  来源发现 · 原文 · 翻译 · 审校 · 权利证据 · 发布决定
                 │
                 │ publication.json 逐项选择 website_public
                 ▼
public 发布系统
  同步输入 · 编辑组织 · 页面 · 样式 · 静态构建 · 部署 · 出版记录
```

public 只读取发布清单中逐项指定的记录、字段和来源，规则见[发布说明](PUBLICATION.md)。private
调整路径或字段时，需要同步更新发布清单或本仓库的同步器。

## 仓库结构

```text
editorial/          站点身份、导航与小组联系配置（site.json）
  books/            成书记录：frontmatter 出版元数据 + 正文为译者引言
  group/            小组工作按期记录：frontmatter 期号元数据 + 正文为本期内容
  archive-taxonomy.json  Archive 的公开编辑分类：topics / persons 词表与逐篇指派
  updates.json      网站与公开工作的简短动态：日期、说明与可选链接
docs/               架构、发布和部署规则
public/             可直接公开的静态资产
scripts/            private 译文与研究资料到构建输入的同步器
  lib/              两个同步器共用的路径、校验与写盘外壳
  lib/research-sync/  研究资料的选择、来源解析与公开字段裁剪
src/components/     展示组件
src/layouts/        站点框架
src/lib/            articles、Markdown 与公开数据适配
src/pages/          长期栏目、子页面和获准正文路由
src/styles/         全站视觉系统
tests/              发布边界、网站结构、Markdown 渲染与样式表验证
  helpers/          页面源码、样式表与发布清单的读取入口
.website-input/     忽略且禁止提交的网站构建输入
dist/               静态构建结果；忽略
```

## 内容归属

站点身份、导航与栏目页面文案在 `editorial/` 与页面中维护。研究事实、作品记录、译文正文和权利
决定来自 private 的 `website_public` 选择；public Git 只保存同步、渲染和展示逻辑。

`editorial/books/` 与 `editorial/group/` 例外，它们是 public 仓库自行维护的正式公开内容：成书的
出版身份与译者引言，以及小组按期记录的工作档案。两者都不经过 private 同步通道，也不进入
`.website-input/`；字段与公开发布规则见[发布说明](PUBLICATION.md)。

`editorial/updates.json` 也由 public 仓库维护，是公开工作变化的单一事实源。首页、`/updates` 与 RSS 读取
同一份数据；动态不是文章，不复制译文或小组正文，不改变 private 对研究
事实与发布决定的所有权。只记录已经确认、可以公开的变化，字段与日期语义见[发布说明](PUBLICATION.md)。

`editorial/archive-taxonomy.json` 属于同一所有权层：它是 Archive 的**公开编辑分类**，由 public
仓库自己维护，回答"这篇关于什么（`topics`）、主要研究谁（`persons`）"。它不经过 private 同步
通道，也不进入 `.website-input/`；引用的文章 id 必须与已公开的文章集合完全一致，缺指派或留下
已撤下文章的旧记录都会让构建失败。`topics` 与 `persons` 与来自 private 的文献事实（题名、作者、
年份、来源）是不同维度：作者回答"谁写的"，`persons` 回答"这篇主要研究谁"，两者不互相复用 id。
