# 发布与访问范围

## 基本原则

文件可读取不等于允许发布；允许网页阅读不等于允许进入 Git；不提供下载按钮也不构成访问控制。
每项内容按精确版本和具体渠道决定公开范围。

## 三种网站状态

| 状态 | 公开页面 | 正文进入 public 静态构建 | 用途 |
| --- | --- | --- | --- |
| 全文公开 | 完整文本与来源说明 | 是 | private 清单中标记为 `website_public` 的译文 |
| 公开目录 | 作品、版本和外部来源 | 否 | 可以公开事实，但不能提供正文 |
| 小组研读 | 只公开目录状态 | 否 | 因版权或协作阶段仅供内部学习 |

若未来需要在网页中提供小组研读正文，应使用独立域名或子域、独立构建和 Cloudflare Access 等
真实访问控制。受限正文不得先进入公共 `dist/` 再依靠界面隐藏。

## 发布渠道

### `website_public`

允许译文进入 public 网站构建，可以生成网页全文；生成 articles 仍不提交到本仓库。

### `group_study`

未来的受限研读渠道。它不属于 public 网站构建，应部署到独立的受保护环境。

## 书籍与正式成果

以中文伊里因科夫名义发行的每项成果至少记录：

- 稳定出版 ID、书名和作者；
- 原文出处（这段文字原本出自哪本书或文集，不是“翻译时用的印本”那种底本概念）；
- 版本号、发布日期和文件校验值；
- 公开、下载和印刷的权利依据；
- 勘误、修订和后续版本关系。

译者不逐本标注：本站的书都由中文伊里因科夫小组制作，这是站点层面的事实，不是某一本书的信息。

private 中存在 LaTeX 或 PDF 不构成发行。正式记录只在对应版本获准后建立；大文件可以作为项目
Release 或外部对象存储中的版本化附件，但其公开身份和维护记录仍由本仓库承载。

### 记录位置与格式

每本书是 `editorial/books/<book_id>.md` 中的一个文件，由 `src/lib/books.ts` 读取并校验，生成
`/books/<book_id>` 页面。frontmatter 保存出版元数据，正文是**译者引言**——由小组撰写、用于介绍这本
书的文字，不是书籍正文，因此可以公开。

```yaml
title: 中文书名
original_title: 原文书名          # 可选
author: 作者
cover: /covers/<book_id>.jpg      # 可选，图片放在 public/covers/
original_source: 原文出处          # 可选；缺省则页面不显示这一行，等信息补齐后再加
category: translation             # 可选，缺省是 translation；另一个值是 digitization
collection: 文集或丛书名           # 可选。多本书写同一个名字，列表页会把它们聚在一起
volume_label: 第一卷              # 可选，只在写了 collection 时才显示，自由格式
rights: 公开、下载与印刷的权利依据 # 可选；未写则“获取与权利”只显示是否提供下载
download:                         # 可选；缺省即页面声明不提供下载
  label: 链接文字
  href: 链接地址
editions:
  - version: v1.0                 # 可以是版本号，也可以是内部修订标识（如 private 仓库的短哈希）
    date: 2026-01-01
    checksum: 文件校验值          # 可选
    note: 版次说明                # 可选
errata: [勘误条目]                # 可选
```

没有 `translators` 字段：本站的书统一由中文伊里因科夫小组翻译制作，不需要逐本标注译者。数字化条目
（`category: digitization`）保留原文语言、不是翻译，同样不需要这个字段——它本来就只对翻译类书籍
有意义，所以彻底去掉了，不是“digitization 不填”的特例。

`category` 决定 `/books` 页面上的分组标题（“译作”“数字化文本”），空分类不显示标题，不需要占位。
`collection` 决定文集内聚：写了同一个 `collection` 的书会在对应分类下聚成一组，标题就是这个名字，
组内按 `editorial/books/` 里文件名的字典序排列——如果顺序要固定成卷次顺序，文件名本身要按顺序命名
（比如 `wenji-01-xxx.md`、`wenji-02-xxx.md`）。

页面上的版次记录默认折叠，只显示当前版本号和日期，点击展开才看到完整版次历史（含 `note`、
`checksum`）——这是一个原生 `<details>`，不需要 JavaScript。

`editorial/books/` 不存在时书籍栏目正常构建为空栏，不需要占位文件。封面之外不放置书籍文件；
未获许可的正文不进入 `public/`，也不进入 `dist/`。

## 当前同步方式

public 读取 `translation/publication.json`，筛选 `website_public`，再把相应 `work.json` 的公开来源字段
与 Markdown 正文合成为 `.website-input/articles/`。private Markdown 自带的 frontmatter 会被移除，网站
使用由 `work.json` 新生成的 frontmatter。

目前同步获准公开的译文，以及生平、服役与黑格尔大会的结构化记录。新增出版物或其他内容类型时，应为该类型建立清楚的数据来源和页面，不把
`internal_public` 或其他未获网站公开许可的正文混入同步结果。

## 生平记录

`/ilyenkov/life` 与 `/ilyenkov/timeline` 使用 private 的 `research/publication.json` 逐项选择的生平记录。首批固定为 1924—1953 年的五个坐标；public 只生成稳定 ID、中文标题与摘要、历史日期范围、可选地点和批准的公开来源。来源限定为 1953 年自传的 DirectMedia 公开书目页与 Filorus 生平页。

原始自传正文、档案文件、扫描件、内部摘录、冲突分析、来源 ID、问题记录与本地路径不得进入 public 构建。来源对具体事实存在冲突时，不在公开叙述中代替研究系统作出裁决：童年迁居莫斯科可以呈现，但 1928／1929 的争议年份不输出。历史日期是研究事实，不是网站时间字段。

## 研究活动记录

服役与黑格尔大会的首批公开记录由 private 的 `research/publication.json` 逐条标记为
`website_public`。public 只生成中文标题与摘要、历史日期或日期范围、地点或状态说明、以及已选定的外部来源链接。
不生成 private 的全文、扫描件、内部置信度、分析、问题记录、日志或本地路径。历史日期是研究事实，不是网站的发布或更新时间。
`/ilyenkov/timeline` 将这些记录与已公开生平坐标按日期排序，不建立第二条研究资料读取通道；当前未覆盖的年代不会被表述为事件空白，作品发表也不进入这条年表。

## 作品目录

`/ilyenkov/works` 的首批条目同样由 private 的 `research/publication.json` 逐项选择。当前包括两部著作、一篇早期理论论文与五篇战时写作；public 仅生成作品 ID、中文与原文题名、原始年份、体裁及批准的外部原文／书目链接；这不代表中文全文、下载或转载授权。战时写作的中文题名为工作题名，仅供目录定位，不表示已有中文译文。未通过选择的作品、总录中的内部核验字段、证据定位、扫描件与正文均不得进入 public 构建。

## 伊里因科夫讨论会

`/research` 的讨论会资料由同一清单逐届选择。当前首批为九个代表节点；public 仅生成届次、中文题名、历史日期、地点或线上形式和批准的公开来源；每届必须有能够定位题名与日期的来源，线上届次还必须有支持线上形式的来源。报告、照片、视频、扫描件、组织细节、统计、内部置信度、缺失项与研究备注均不得进入 public 构建。页面中的日期是会议历史事实，不是网站的发布或更新时间。

## IFI 研究网络与 symposium

International Friends of Ilyenkov（IFI）及其 symposium 也由 `research/publication.json` 逐项选择。public 仅生成组织名称、缩写、成立年份、中文定位、官网，以及每届的中文题名、历史日期、地点与官方来源。活动来源必须明确支持题名、日期和地点；成员、成员资格判断、webinar、报告、视频、照片、附件、下载情况、统计、日志、问题记录与本地路径均不得进入 public 构建。2021 年计划活动不因资料存在而被表述为已发生会议。

## 研究者阅读入口

`/research` 中的研究者卡片由同一清单逐项选择。public 只生成中文与原文姓名、简短定位、被选研究文本的中俄题名、外部来源和已有的 `/archive` 阅读入口。每项必须是所选作者的 `research_author_text`，其来源必须关联该作品，archive 条目也必须已公开且题名匹配。作者履历、机构、完整书目、档案、扫描件、未选文本、内部分析、日志、问题记录与本地路径均不得进入 public 构建。

## 外部资料站点

`/research` 中的外部资料站点同样由 `research/publication.json` 逐项选择。public 只生成站点的中文与原文名称、简短中文定位、批准的站点入口和分类链接；每个分类必须由来源页中的对应分类或明确选择的公开文件支持。本站不导入或转载外站正文、附件与下载内容，也不输出本地采集文件名、抓取记录、内部说明、未选资料或路径。外部链接只用于资料定位，不表示本站拥有转载或下载授权。

## 小组公共记录

`/group` 不重复汇总翻译、书籍或研究资料，只记录中文伊里因科夫小组自身的活动、会议、合作事项与署名文章。当前没有完成公开选择的小组记录，因此不建立空的 private 数据结构或同步通道，页面仅显示栏目定位与当前状态。

未来活动与会议必须在 private 中逐项批准后才能进入网站；内部会议只允许输出明确获准公开的摘要。小组署名文章若获准全文公开，正文统一进入 `/archive`，小组页只记录其组织语境和阅读入口。成员名单、内部协作、版权沟通、未选会议、联系方式、网站时间字段与内部路径不得进入 public 构建。

## 生平阶段入口

`/ilyenkov/life` 将五条已公开的 1924—1953 年生平坐标，与既有服役、作品和国际活动记录组织为五个阶段，并把读者带回能够逐项核验的年表、活动页与作品目录。它仍不是完整传记：1954 年以后没有逐项公开选择的任职、家庭、晚年、逝世或回忆材料，不得以叙述、摘要、路径或附件形式进入 public 或 `dist/`。
