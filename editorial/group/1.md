中文伊里因科夫小组成立以来，我们一直在尝试收集、整理和翻译伊里因科夫及相关研究者的著作与文献。随着工作的推进，我们逐渐发现，翻译并不只是将一种语言转换为另一种语言。原始文献的获取与数字化、文本结构的整理、术语的统一、译文的审阅和修订，以及最终的排版与发布，都是这项工作不可缺少的部分。

这些工作最初并没有一套完整的规范。许多方法是在实际翻译中逐渐摸索出来的：遇到问题，寻找解决办法；发现错误，调整工作方式；当某种做法反复证明有效时，再将它整理为可以重复使用的规则。

如今，我们决定将这些工作流程、相关规范和部分辅助工具公开，希望让小组的翻译工作更加透明，也为其他有类似需要的读者和研究者提供参考。

## 一、为什么要公开翻译工作流程？

对于哲学文献，尤其是涉及复杂概念和理论传统的著作，译文的质量不仅取决于个别语句是否通顺，还取决于对原文的理解、术语在不同语境中的使用，以及各个部分之间能否保持一致。

在实际工作中，我们遇到过许多具体问题。例如，如何从扫描文献中获得尽可能可靠的文本？如何处理原文中复杂的注释、段落和章节结构？同一个哲学术语在不同语境中是否应该采用同一种译法？当两次审阅提出不同意见时，又应该如何保留讨论过程并作出判断？

这些问题很难仅凭一份提示词或者一次翻译任务解决。随着文献数量增加，如果没有相对明确的工作方式，许多已经解决的问题便可能反复出现，先前积累的经验也难以传递给新的参与者。

例如，一篇相对独立的文章，通常可以围绕一份原文和一份译文完成整理与审阅。但在处理篇幅较长、章节较多的著作时，还需要考虑如何分批推进、如何在不同章节间维持术语一致、如何保存审阅记录，以及在修改译文之后怎样确认相关问题已经得到解决。工作对象和规模的变化，使我们逐渐认识到，有必要将这些环节组织成更加明确的流程。

因此，我们开始将实际使用的工作方法写成规范，记录不同阶段需要完成的任务、应当保留的材料，以及需要人工检查和裁决的环节。

这些规范是我们当前实践的阶段性成果。我们希望通过公开，使它们能够被更多人理解、检验，并在交流和实际使用中继续完善。

## 二、从文献数字化到译文形成

我们目前使用的工作流程大致包括文献数字化、文本预处理、翻译、审阅、统稿和成书等环节。

首先是原始文献的整理。

不同来源的文献具有不同的形式：有些已经包含可以提取的电子文本，有些是由纸质书扫描得到的 PDF，还有一些采用 DJVU 等格式。它们所需要的处理方式并不相同。

我们的目标不仅是得到一份能够复制的文字，还要尽可能建立一份结构清楚、便于核对的工作文本。在这一阶段，章节、段落、脚注、原文页码以及文本中的不确定之处，都需要得到适当处理。

在书籍翻译中，我们会对文本进行分组和分批处理，为相关单元建立可以追踪的标识。这使翻译、审阅和修订能够围绕相对明确的文本范围展开，也便于在发现问题时返回原文核对。

随后进入翻译和审阅阶段。

对于较长的著作，我们将其划分为可以逐步完成和检查的工作单元。翻译完成后，还需要经过独立审阅、问题处理和必要的统稿，使不同章节之间尽可能保持一致。

术语管理贯穿这些阶段。我们将部分重要术语及其译法记录下来，并保留必要的语境说明，使它们能够在后续工作中得到参考和修正。

最后，经过整理和确认的 Markdown 文本还可以进一步用于 LaTeX 排版和成书。文献整理、翻译验收和出版准备虽然相互关联，却各自有不同的检查要求。文本能够成功排版，只能说明它通过了相应的技术处理，并不能代替内容审校。

## 三、Agent 能够帮助我们做什么？

人工智能 Agent 的发展，使个人或小规模研究团体能够尝试承担过去需要投入大量重复劳动的文献整理工作。

在我们的实践中，Agent 不仅可以协助翻译，还可以根据明确的任务要求进行文本提取、结构整理、术语检查、译文比较、审阅记录和部分排版处理。

在现有工作流中，我们主要区分三个角色：Operator、Reviewer 和 Owner。

Operator 负责具体的翻译任务、自查与工作交接；Reviewer 负责相对独立的审阅，检查译文中可能存在的误解、遗漏、术语问题和表达问题；Owner 则负责对疑难问题、重要术语和最终质量作出判断。

其中，独立审阅尤其重要。我们要求 Reviewer 由没有参与相应 Operator 生产过程的独立 Agent 或会话承担，尽量减少审阅过程对既有翻译判断的依赖。

不过，独立审阅并不等于独立验证。即使两个 Agent 分别开展工作，也可能因为依赖相同资料、采用相近的处理方式或存在类似的认识局限，而产生相同的错误。因此，独立审阅仍然需要以原文核对为基础，也不能代替研究者对理论内容的理解。

通过明确任务边界、区分工作角色以及保存必要记录，我们希望减少一些可以避免的错误，使翻译和修订过程更加清晰，也使不同参与者能够了解某一处译文是怎样形成和修改的。

Agent 的作用，是帮助我们执行和检查具体工作；如何理解一段哲学论证、如何裁决有争议的译法、某份译文是否已经适合公开，仍然需要由人来承担责任。

## 四、公开仓库包含什么？

2026 年 10 月 14 日，我们在 GitHub 发布了翻译工作流的首个公开版本 v0.1.0。

**项目地址：** [https://github.com/hoshF/ilyenkov-translation-workflow](https://github.com/hoshF/ilyenkov-translation-workflow)

公开仓库主要包括文献数字化、文章与书籍翻译、独立审阅、术语管理、统稿以及文本成书的工作规范，同时提供少量 Python 辅助工具、LaTeX 模板和教学示例。

这些文件是一组源于实际工作的、可以被阅读和复用的规范与工具。使用者可以根据自己的需要选择其中某一部分，也可以修改它们以适应不同语言、作品和研究领域。

例如，正在整理扫描文献的读者可以只参考数字化规范；已经开展翻译的研究者可以借鉴 Operator 与 Reviewer 的分工；希望组织多人协作的团体，则可以参考文本单元划分、术语记录和审阅交接的方法。

除了提供可供复用的方法，我们也希望通过公开工作规范，使读者能够了解小组如何组织翻译、处理问题并进行质量检查。公开这些方法本身不能证明译文的质量，却可以为讨论和评价我们的工作提供更多依据。

仓库中的工作流文档及原创教学文本采用 CC BY 4.0 许可证，相关程序和代码文件采用 MIT 许可证，具体适用范围以仓库中的许可证文件为准。

工作流规范的公开与具体文献的使用授权是两回事。小组收集的原文、译文和其他研究材料仍须遵守各自的版权及使用条件。

我们欢迎读者参考、修改和使用这些方法，也欢迎通过 GitHub Issues 等方式提出疑问、指出问题或提供改进建议。

## 五、一个仍在发展的工作流程

这份工作流是在实际使用中不断形成和调整的。

我们目前采用的许多规则，都与此前遇到的具体困难有关。随着文献类型、翻译任务、参与人数和工具条件的变化，现有方法还会遇到新的问题。某些规则可能需要补充，某些操作也可能逐渐变得不再必要。

因此，我们将首个公开版本作为一个可以继续发展的起点。

今后，小组将根据实际工作的经验继续修订相关规范，更新辅助工具，并逐步完善可供他人参考的示例。重要的版本变化将在 GitHub 仓库中保留记录。

**本文也将随着工作流的发展适时修订。** 文章的首次发表日期将予以保留；当工作方式发生实质性变化时，我们会相应更新本文的说明。具体的操作规则和最新文件则以 GitHub 仓库为准。

我们希望公开的不只是翻译工作的成果，还有这些成果得以形成的方法。翻译工作中积累的经验，不应当只停留在个别参与者的工作记录里，也可以通过整理、交流和改进，成为其他研究者能够利用的资源。

这套工作流仍然处于发展之中。我们欢迎读者使用其中的方法，也欢迎针对具体规范提出批评和建议。
