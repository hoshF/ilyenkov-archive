# 成书排版：给 agent 的提示

本文只写**还会犯的错**。已经落地的设置不在这里重复——每一项的理由都写在
`main.tex` 与 `preamble.tex` 里那条设置的旁边，改它时自然会读到。

排版这件事的麻烦在于：**错了不报错**。缺字形有警告，但设了不生效的旋钮、被 TeX 悄悄
丢弃的空白、把标点当文字排进文本层，都不会报错——只会在某一页显出来，或者根本不显
出来（只在别人复制正文时才发现）。所以下面每条都配验证办法，不要凭观感下结论。

## 一 先立基线，改完对上

改任何版式之前，记下当前产物的可比指标；改完逐项对照。**重构排版代码时尤其必要**——
它应当完全不改变输出，而这一点只能靠比对证明，不能靠"看着一样"。

```python
import fitz, hashlib
d = fitz.open("book/build/main.pdf")
print(d.page_count, hashlib.sha256("".join(p.get_text() for p in d).encode()).hexdigest()[:32])
```

再加：开本、正文字号、行距、自然字距、用到的字体表。

**版本页的 commit 戳会让文本 SHA 变**，比对时归一掉，否则每次都"有差异"。

## 二 量法：四个反复量错的地方

排版的每个判断都建立在测量上，而这四处每次都可能重犯：

**字距要取段末行。** 参与两端对齐的行会被拉伸，量出来能比字号还大（曾量到 10.56pt >
字号 10.5pt），据此调出来的是错的。只量右边未顶到版心的行。

**版心左右界分奇偶页。** `inner`/`outer` 在对开两面互换。拿奇数页的边界核偶数页，
会得出"标题没居中"的假结论；只按一个边界找脚注标号，会漏掉一半。

**行首标点会伸出版心。** xeCJK 的悬挂让以「“」「（」起行的行左出边界一两毫米。
用"最左/最右"量版心会偏大，要取**众数**边界。

**不要靠"字号＋是数字"认元素。** 注文里满是年份和页码，与标号同字号——曾据此把
1936、1970 算成脚注标号，报出根本不存在的"每页重编不连续"。按位置认。

> 通则：报出问题之前，先问这个测量本身会不会错。本文一半的篇幅来自量错而非排错。

## 三 设了不生效的旋钮

改字距、间距一类设置时，先确认它真的起作用。

- **`LetterSpace` 对汉字间距完全无效。** 它在 `\setCJKmainfont` 里放了很久，从来没起
  过作用。管汉字间距的是 xeCJK 的 `CJKglue`。
- **`CJKglue` 必须写在 `\begin{document}` 之后**，写在导言里会被 ctex 在开篇重新
  初始化覆盖，不报错、不留痕迹。

> 验证一个旋钮是否生效，给它一个**夸张的值**做小样（如 `0.2em`），看有没有变化。
> 用目标值试，变化太小，分不清是没生效还是值不够。

## 四 页首的 glue 一律被丢弃

这不是某一处的毛病，是 TeX 的分页行为：**凡是靠 glue 撑出来的空白，落在页首都会消失**。
`section/beforeskip` 如此，`\vspace*` 实测在这里也保不住。

要让空白在页首也存在，把它做进那一行**自己的盒子**里——盒子的高度谁也丢不掉：

```latex
\section*{\rule[0pt]{0pt}{42pt}#1}
```

给任何元素加"上方留白"时都会碰到这一条，不限于节标题。

## 五 新书要自己决定的：强调怎么排

原文的斜体强调不能照排斜体（汉字没有真正的斜体，伪斜是变形）。三条路，**取舍取决于
这本书强调跨度的分布**，先量再定——统计各处强调的字数，看长跨度占全部强调字数的比例：

| | 长处 | 代价 |
|---|---|---|
| **黑体**（现行） | 换字面而非字重，长跨度也不发黑 | 必须点名 `Heiti SC Medium`——macOS 的「Heiti SC」默认解析到 Light，与宋体等重，看不出是强调 |
| **伪粗** | 一眼跳出，字面不变、与正文不割裂 | 长跨度连成黑块，比节标题还重；笔画靠描边撑出，小字号付印可能糊 |
| **着重号** | 中文传统做法，长跨度撑得住 | `\CJKunderdot` 默认把点当**文字**排，全进 PDF 文本层——复制正文带出一串「•」，PDF 内搜索在强调处断开 |

本书 30 字以上的长强调占全部强调字数的 62%（最长 144 字），故取黑体。若新书的强调多为
短语，伪粗更醒目。

要用着重号，把符号换成画出来的图形即可避开文本层问题：

```latex
\usepackage{tikz}
\newcommand{\bookdot}{\tikz[baseline]\fill (0,0) circle (0.135em);}
\xeCJKsetup{underdot/symbol={\bookdot}, underdot/depth=0.34em}
\renewcommand{\emph}[1]{\CJKunderdot{#1}}
```

**斜体不等于强调，正文里也是。** 底本的斜体承担三件事，只有一件是强调：

| 斜体在做什么 | 例 | 怎么排 |
|---|---|---|
| 强调 | `*лишь способ научного изображения*` | 黑体 |
| 脚注著录作者名（俄文文献体例） | `*Лейбниц Г.В.* Новые опыты…` | 楷体，本书 71 处里 70 处如此 |
| 正文里的署名与行内著录 | `(курсив мой — *Э.И.*)`、`(*Маркс К.* Grundrisse)` | 楷体，本书 11 处 |

脚注那侧**靠位置**就能区分（在脚注里即另走一个命令）；正文里没有位置可依，只能靠形态，
故判据必须**窄**：署名只认穷举的那几种写法，著录要求「姓氏＋空格＋缩写」。
**判不准的一律留给强调**——当成强调而其实不是，只是显得重一点；反过来会抹掉原文的信息。

判据写在 `md_to_latex.is_apparatus`，配了测试钉住正反两侧。

## 六 交给所有者定，不要自作主张

- **长标题的断点落在词中间**（「大卫·李／嘉图的」）。中文没有词边界标记，TeX 在任意
  两个汉字间都可断，自动改不了。逐条按文意指定断点可以修，代价是行长不齐——这是编辑
  决定。本书所有者选了保持齐整。
- **开本、字号、行距一类与参考本不符之处**：如实报出差值与代价（页数变化最直观），
  让所有者定，不要"顺手对齐"。

## 五·五 归错因：换掉记号，其实该换位置

脚注行的标号一度从圈数字改成阿拉伯数字，理由是「圈数字又小又吊起来，与注文脱开」——
**实测没错，归因错了**。毛病在**上标与字号**（5pt 上标，注文 7.5pt），不在记号本身。
参考本（已出版中译）两处都用圈数字，脚注行的 ① 落在基线上、与注文同字号，一点不脱开。

> 通则：**改之前先分清「这个坏效果由哪个属性造成」**。记号、字号、位置、字重是四件事，
> 混在一起看只会得出「这个记号不行」。手边有参考本时，量它——它已经解决过同一个问题。

顺带一条：本书脚注**每页重编**，用阿拉伯数字时每页第一条都是孤零零的「1」，易被读成
条目编号；圈数字自带「这是标号」的信息。

## 六·五 重编译会让页码全变

排版一改、译文一改，页数与断行就变。**上一版按页码记的批注一律失效。**
所以校阅的批注定位用锚点 `chNNN-pNNNN` 而非页码（`scripts/read_pdf_notes.py`
把划线直接读成锚点），问题记在各书的 `REVIEW_LOG.md`；交付新版时须明说旧批注作废。

推论：不要改一处就编译一次。攒够一批修正，一起改、一起签、编译一次。

## 七 收尾核查

每次改完版式跑一遍：

- [ ] 缺字形 0 处（构建脚本会报）
- [ ] `Underfull \vbox` / `Overfull \hbox` 数量没有变多
- [ ] `pdftotext` 后文本层无杂字符（着重号、装饰符一类不该出现）
- [ ] PDF 内搜索：随手取几句含强调的正文，应当都搜得到
- [ ] 书眉无折行（数书眉带内的文本行数，多于"页码＋眉文"就是折了）
- [ ] 与基线比对：页数、文本 SHA（归一 commit 戳）、开本、字号、行距、字距
- [ ] **版本页 commit ＝文件名 commit ＝`git rev-parse HEAD`**——必须在提交之后构建，
      提交前构建会刻上上一个 commit（此错犯过两次，都是交付时才发现）

> 推论：**git 历史不可重写**。刻记是发出去的 PDF 回溯到源头的唯一凭据，重写历史会让
> 每一份已发副本的刻记指向不存在的 commit。所以就算历史里躺着已被取代的大文件
> （本项目是 12.9 MB 的旧字体），也不去抹——见 AGENTS.md 的硬规则。
